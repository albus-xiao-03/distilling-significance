**Hackathon prototype plan: zero-shot significance pseudo-labels from an unchanged behavior model**

| | |
|---|---|

| Gate | Implementation starts only after the owner answers the decisions in [§10](#10-owner-decisions). |
| Scope | Investigation results, the representation design, the experiment, phases, risks. |

---

## 1. Goal and hypothesis

**Goal.** Build a pipeline that:

1. takes an open dataset of real people's behaviour;
2. rewrites it as **sequences of observations and the human decisions about whether each one deserved further attention**, in BehaviorGPT's own input format;
3. asks BehaviorGPT, **unchanged (no fine-tuning, no retraining)**, to predict that decision for new observations;
4. turns those predictions into **pseudo-labels**, giving a supervised-learning dataset;
5. measures how good the pseudo-labels are against the real decisions, and how much of a gold-trained classifier's quality a classifier trained on them recovers ("distilling significance").

**Hypothesis.** BehaviorGPT predicts what a person acts on next. If "this observation deserves further analysis" is written as **the person choosing that observation**, then its pretrained next-choice ranking is a zero-shot significance scorer. How the sequence is represented (what counts as a choice, how sessions and dismissals are encoded) changes how good that scorer is. That representation effect is the experiment.

**What would count as a result.** Either outcome is reportable:
- *Positive:* zero-shot pseudo-labels clearly beat chance and simple baselines, and a student trained on them recovers a meaningful share of the gold-trained student's quality.
- *Negative:* the representation does not carry the signal. We report which variants failed and by how much.

## 4. Core idea: significance is a choice

BehaviorGPT can only say one thing: *"given what this person did, how likely are they to act on item X next?"* Everything else is representation. The design follows three rules:

1. **"Deserves further analysis" = the person chooses the observation.** This is the model's native positive action. A flagged observation becomes a choice event (`View`, or `View` + `Order` in some variants).
2. **"Dismissed" is never a `View` in the person's own history.** The model reads any view as interest (README "Events"), so dismissals appear only by being left out (llms.txt principle 6), as **candidates to score**, or in a separate contrast context (variant R3).
3. **Never score an observation from a history that already contains it.** Seen items are pushed down on purpose (anomaly README §2), which would bias every score.

## 5. Significance Sequence Format (SSF)

A dataset-agnostic format. Each dataset gets one small adapter that writes it.

### 5.1 Observation → catalog row (MIND adapter)

| Catalog column | MIND value | Note |
|---|---|---|
| `id` | News ID (`N37378`) | Unique |
| `name` | Title | Primary embedded text. Ablation: title + abstract. |
| `brand` | null | No publisher field in MIND |
| `categories` | `"<Category>, <SubCategory>"` e.g. `"sports, golf"` | Embedded and split into keywords |
| `keywords` / `search_keywords` | Wikidata entity labels / surface forms | Augmentation only |
| `image_url` | null | Text-only embedding (allowed; "minimum viable catalog") |
| `event_type`, `group` | `"product"` | Required constant |
| `market` | `"US"` | |
| `sales_since`, `timestamp`, `frequency` | **null in the main run** | Keeps the representation test clean. A popularity variant computed only from clicks *before* the evaluation day is a stretch ablation (re-embedding the same file name). |
| `price`, `currency` | null | Display-only anyway |

Embedded with `reference_time` = start of the MIND evaluation day.

### 5.2 Decision → events, and one record per decision episode

```jsonc
// ILLUSTRATIVE ids/values. One SSF record = one "triage episode": a person, their past decisions, and new observations to decide on
{
  "episode_id": "dev-91",                // MIND impression id
  "subject_id": "U397059",               // the person making decisions
  "time": "2019-11-15T10:22:32",
  "context": {
    "flagged":   [["N106403", "N71977"], ["N97080"]],   // sessions of past observations they chose, oldest first
    "dismissed": [["N5521", "N7781", "N9003"]]          // observations they were shown earlier and passed over
  },
  "candidates": ["N129416", "N26703", "N120089", "N53018"],  // new observations needing a decision
  "gold": {"N26703": 1, "N120089": 1, "N129416": 0, "N53018": 0}  // real decisions; NEVER sent to BehaviorGPT
}
```

Where context comes from in MIND:
- the impression's `History` column (clicks from weeks 1–4) forms the oldest `flagged` session;
- the same user's **earlier** impressions supply more `flagged` sessions (clicked) and `dismissed` sessions (shown, not clicked). These are always strictly earlier in time.

Gold labels are stored separately from what the teacher reads, so leakage is structurally impossible.

## 6. Zero-shot teacher

### 6.1 Scoring

For an episode with history `H` and candidates `c₁…cₙ`:

```
s(c | H) = score of c from client.complete(H, limit=len(chunk), filters={"id": chunk})
```

Candidates are sent in chunks of ≤ 100 ids. Every call:
- is cached on disk by (catalog, history, ids), in SQLite under `.temp/cache/`;
- is retried with backoff on 429/5xx;
- carries **no `user_id`**, so nothing is recorded on the account.

The prior `s(c | ∅)` (empty history) is cached once per item.

### 6.2 Representation variants (the core experiment)

| Id | History sent to BehaviorGPT | What it tests |
|---|---|---|
| **R0** native | All flagged observations as `View`s, one session, oldest first | The plain "a read is a view" mapping (baseline representation) |
| **R1** explicit decision | Each flagged observation as `View` then `Order` | Does encoding "flagged" as a *choice* (not just a look) sharpen the signal? |
| **R2** triage sessions | R1, but split into sessions: one per earlier decision episode, plus the old history as the first session | Does episode structure help? *(multi-session histories are SDK-only)* |
| **R3** contrastive dismissal | `s(c│H_flagged) − λ·s(c│H_dismissed)`, with dismissed observations as `View`s in a **separate** context; λ = 1 (no tuning) | Can "what they passed over" be used without the model reading it as interest? |
| **R4** prior-normalised | `s(c│H) − s(c│∅)` (a pointwise-mutual-information-style score); combinable with R3 | Removes "everyone clicks this" popularity, leaving what is specific to the person |
| *R5 (optional)* explicit rejection | Dismissed observations as `AddToCart` → `RemoveFromCart` inside R2's sessions | Whether a "considered, then rejected" funnel encodes dismissal. **SDK-only events; ablation only.** |

History length is capped at the last *K* events (K = 50 by default, adjusted after the Phase 0 measurement).

### 6.3 From scores to pseudo-labels

Raw scores are on a per-history scale (not probabilities), so labels are assigned by **rank within an episode**:

- **P1, zero-gold (main):**
  - the top *k* candidates per episode → `1`, with *k* = 1 (MIND impressions contain at least one click; verified on data in Phase 1, else *k* = max(1, …));
  - the bottom 50 % → `0`;
  - the rest → **abstain** (no label);
  - `confidence` = the rank margin.
- **P2, few-shot calibration (ablation, clearly labelled):** a gold *seed* of ≤ 5 % of episodes fits a 1-D logistic calibration and a base-rate threshold. BehaviorGPT is still untouched; only this downstream mapping sees gold.

## 8. Evaluation

### 8.1 Teacher quality against real decisions (MIND dev split)

- **Metrics:** AUC (mean per episode), MRR, nDCG@5/@10 (MIND's standard set); for binary pseudo-labels, precision/recall/F1, Cohen's κ against gold, and coverage vs. accuracy as the abstention band widens. **95 % bootstrap CIs** over episodes.
- **Baselines (no BehaviorGPT):**
  - random;
  - popularity (clicks on the item in impressions *before* the episode);
  - recency;
  - TF-IDF similarity between the candidate's title and the person's clicked titles.

  Popularity is known to be strong on news, so beating it is a stretch target, not a requirement.

### 8.2 Distillation (the "supervised dataset" payoff)

The **student** is a scikit-learn logistic regression on features that don't use BehaviorGPT:
- TF-IDF of the title;
- category and subcategory one-hots;
- the person's past share of clicks in that category and subcategory;
- prior popularity;
- history length and episode size.

| Student trained on | Role |
|---|---|
| Gold labels (train split) | Upper bound |
| **BehaviorGPT pseudo-labels (train split, gold hidden)** | **The result** |
| Popularity-heuristic labels | Simple-teacher comparison |
| Random labels | Floor |

All students are evaluated on the **gold dev split**.

**Headline number:** recovery = (AUC_pseudo − 0.5) / (AUC_gold − 0.5).

### 8.3 Hackathon success targets

1. **End to end:** the pipeline runs on ≥ 1,000 dev episodes, fully cached and reproducible.
2. **Above chance:** the best zero-shot variant beats random with a 95 % CI that excludes AUC 0.5.
3. **Representation effect:** at least one of R1–R4 differs from R0 beyond its CI. Reported in whichever direction it goes.
4. **Distillation:** report recovery. Target ≥ 50 %.

## 11. Risks and mitigations

| Risk | Effect | Mitigation |
|---|---|---|
| Headlines are far from the retail items the model saw most | Weak signal | R0–R4 and the TF-IDF baseline make it measurable; a title+abstract ablation; a negative result is still a result |
| Raw scores aren't probabilities and differ per history | Mis-calibrated labels | Rank-within-episode labelling (P1); PMI normalisation (R4); optional P2 calibration |
| Seen-item suppression | Biased scores | Rule 3 of §4: candidates are never in their own scoring history |
| Dismissals read as interest | Inverted signal | Rule 2 of §4; dismissals only in R3's separate context or the R5 ablation |
| Undocumented rate limits and history length | Stalls, refusals | Phase 0 measurement; cache; throttle; cap history at K |
| History timing is synthetic (SDK re-stamps events) | Time features lost | Accepted. Order is preserved, which is what the variants test. |
| Only 2 catalog slots; embedding takes minutes | Blocked or slow iteration | One catalog for all variants; the popularity ablation re-uses the same file name |
| Licence (MIND non-commercial) | Limits reuse | Fine for research and a hackathon. The data card states the inherited restriction. |
| Leakage | Inflated results | Gold kept out of SSF context; popularity only from strictly earlier impressions; train/dev split by MIND's own time split |
| "Customer behaviour" vs. news readers | Mismatch with the brief | D1; SSF and the teacher are dataset-agnostic, so a commerce adapter can follow |
